# EIEL Tick-Native Authority and Generation-Era Supersession Index

Status: `AUTHORITATIVE_CURRENT`
Scope: Lifecycle V2 / `EIEL_FULL_EVOLUTION_V1` execution, artifact lifecycle,
qualification scope, and production-science interpretation
Effective date: 2026-08-20

This index resolves current guidance without changing sealed reports, receipts,
published documents, or historical filenames. It is an interpretation and
supersession authority for generation-era material, not a new execution or
qualification grant.

## Non-negotiable current rule

For active Lifecycle V2 / `EIEL_FULL_EVOLUTION_V1`, `absolute_tick` and
`total_ticks` are authoritative. Resident-owner, dispatch, refill, source,
event, report, checkpoint, science, reducer, and archive spans are explicit
tick quantities. Generation-shaped fields may enter only through the named
`legacy_generation_route_v1`, a historical reader, or an explicit heritage
turnover adapter. They are not active runtime, allocation, checkpoint,
qualification, or science authority.

Qualification has three separate dimensions:

1. `BOUNDED_ROUTE_QUALIFIED`
2. `LONG_HORIZON_RUNABILITY_QUALIFIED`
3. `SCIENCE_ROUTE_QUALIFIED`

A bounded result does not imply either later dimension. Current B136
long-horizon evidence must cover at least 5,000 absolute ticks on the exact
W32/P256/C512 full route and satisfy the governing memory, event, continuation,
checkpoint, and resource-safety obligations. B140 and B144 are not admitted by
this index.

## Authority order

When sources conflict, use this order for the scope above:

1. Current source behavior and accepted source-bound receipts.
2. Root `AGENTS.md` and the current QualPrep, qualification-preservation, and
   expensive-execution procedures.
3. This index, the active artifact-lifecycle runbook, current campaign README,
   current schemas, and current actor examples.
4. Explicit legacy compatibility contracts for their named legacy route only.
5. Historical reports, snapshots, incoming drafts, and register entries as
   evidence of what was decided for their frozen target—not current design
   guidance and not authority for a broader qualification dimension.

Timestamp, filename, path proximity, `Q6`, `PASS`, or `qualified` text alone
does not override this ordering.

Guidance audits use exactly these classifications: `AUTHORITATIVE_CURRENT`,
`LEGACY_COMPATIBILITY_GUIDANCE`, `HISTORICAL_IMMUTABLE`, `STALE_DANGEROUS`,
`CONTRADICTORY`, and `UNKNOWN`. No surface listed in this index remains
`UNKNOWN`. The contradictory active runbook, README, schema, and actor-example
surfaces identified by the reform were corrected in place and are classified
below by their resulting current state.

## Historical-only campaign marker

When a historical campaign is copied or re-materialized outside its sealed
location, mark it with the current campaign schema’s `authority` object:

```yaml
authority:
  classification: HISTORICAL_IMMUTABLE
  execution_permission: NON_EXECUTABLE_HISTORICAL
  superseded_by: governance/EIEL_Tick_Native_Authority_and_Generation_Era_Supersession_Index.md
  reason: Preserved generation-era fixture; not a current execution target.
```

The marker is machine-readable and intentionally not accepted by the canonical
execution compiler as launch authority. Do not add the marker by editing a
sealed historical document merely for cosmetics; this index supplies the
disposition for preserved in-place material.

## Review and maintenance rule

Any new active example, schema, runbook, or agent-facing help for Lifecycle V2
must use absolute ticks. The standalone tick-native firewall in CI checks the
current guidance, route schema branches, checkpoint roles, qualification
dimension/evidence contracts, and selected bounded regression sentinels.
Changes that intentionally extend legacy or heritage support must name the
route/adapter and add a narrow compatibility test; they do not weaken the
active tick-native branch.
